# Madrasty Premium Visual Polish — Design specification
**Status:** Planning only; owner explicitly requested a whole-app visual-only plan. Proposed design tokens and mockups need visual approval in P01 before broad implementation. Baseline `b90fab0bec705b4bf25eb8e43f4f6f8eaa6de77a` (main after PR #32).

## Objective
Make the entire product feel like a carefully crafted modern native mobile application: calm, expressive, smooth, crisp, tactile and consistent. This is not a new workflow redesign. Apply the same level of craft to every visible element for Admin, Teacher, Guardian, public/auth, capability-restricted roles, native Android, iPhone/iPad installed web/PWA, browser and desktop. No page, button, word, icon, circle or terminal state omitted. Reference is the three supplied workout-ad screenshots: large confident headlines, very clear numbers, deep forest hero with nested soft cards, rounded capsule CTA, light warm off-white canvas, controlled high-contrast accent, smooth ring/step controls, spacious separation, floating navigation, restrained depth. Do not copy the ad overlay, brand, fitness features, text, logo or proprietary typography. User wants the quality, not a clone.

## Proposed visual system (P01 prototypes; not locked until owner approval)
Use semantic color and shape tokens in Web and Compose. The light appearance follows the existing warm neutral and forest palette. The owner updated the dark direction on 2026-11-28 to use a black canvas `#000000`, charcoal cards `#1C1C1C`, inset surfaces `#262626`, white primary text `#FFFFFF` and secondary text `#B8B8B8`. Dark role heroes use the charcoal card surface and retain the original notebook artwork. The school logo, action accents and semantic danger, warning and success states retain their own colors. The visual reference is the layered dark appearance of iPhone, ChatGPT and Spotify. The project palette has measured contrast pairs in the [standards audit](STANDARDS_AUDIT.md). [Apple Dark Mode](https://developer.apple.com/design/human-interface-guidelines/dark-mode) · [ChatGPT appearance](https://help.openai.com/en/articles/11958281-updating-your-visual-experience-on-chatgpt) · [Spotify design guidelines](https://developer.spotify.com/documentation/design)

### Type
System font on iOS/web German with normal fallback; Compose platform text; evaluate rounded display face only if licensed, local and appropriate, not copy unknown ad font. Keep IBM Plex Sans Arabic and tune optical size/weight/line spacing; no letter-spacing on Arabic; never break glyph joining. German headline proposed 32–36/700–800, section 20–22/650–700, body 16–17/400–500, secondary 13–14/400–500, label 14–15/600, primary action 16/650–700, hero KPI 34–44/700–800; scale responsive and with accessibility. Arabic use optical equivalent and generous 1.5–1.65 line-height; preserve readable diacritics and bilingual names. Numeric data tabular where helpful, locale format unchanged, bidi isolate money/dates/IDs. Large figures only where meaningful, not entire forms. Keep 200% zoom/reflow and Android fontScale. No fixed text heights or indiscriminate truncation; full name accessible.

### Geometry and visual hierarchy
Spacing scale 4/8/12/16/20/24/32/40; mobile content inset 16–20, section gaps 20–28, grouped rows 12–16 padding. Hero 28–32 radius, standard card 20–24, inset 14–18, inputs 14–18, primary CTA capsule when appropriate, chips pill, icon buttons circular. Match nested corner radii; no excessive border stacking. One dominant focal point per screen, secondary controls subdued but discoverable. Preserve dense table readability instead of turning every row into oversized cards. Native Compose shapes/tonal elevation use platform primitives. Subtle 1px separators for lists, soft one/two-layer shadow only on raised surfaces, consistent upper highlight on selected elevated surfaces. No neon gradients everywhere, no glossy skeuomorphism.

### Material, navigation, controls
iOS PWA: selective translucent/blurred floating tab bar and sheets, opaque accessible fallback for unsupported/reduced transparency/high contrast or performance limits. Never pretend web CSS is native Liquid Glass. Ensure content inset accounts for bar + safe-area + keyboard and screen reader access. Android: Material3 NavigationBar/rail and platform ripple, rounded shapes, edge-to-edge, no forced iOS imitation. Desktop sidebar/columns remain functional and restrained. Maintain exact tabs, order and navigation. Native pickers/checkboxes/switches retain real input semantics; improve surrounding shell only. Button family primary/secondary/tertiary/destructive/icon, consistent disabled/loading/selected/error/focus/hover/pressed states. Interactive area >=44 CSS px on web and >=48dp native (project targets); small icons can be within larger hit area. Icon optical size 20/24, consistent stroke and direction; labels accessible, only directional icons mirror. Charts/rings show actual numbers and text, never decorative invented progress. No gradient or blur behind reading surfaces.

### Motion
Immediate reversible feedback, ~100–160ms press and 140–220ms settle, existing shared ease-out (0.23,1,0.32,1). Only opacity/transform on small elements where possible; preserve existing no-entry-animation contract for repeated routes. Do not block clicks, scroll, or navigation for animations. Compose ripple and native transitions, no extra delay. Reduce motion removes nonessential transforms and pulses. No layout-thrashing animation, transition:all, huge blur, zero-scale entrance, arbitrary timeouts, scroll-position reset or artificial loading. Actual traces required; perceived speed cannot be inferred from screenshot. Define baseline before making motion changes.

### Every visible item
Inspect each rendered glyph/string, headings, paragraphs, labels, placeholders, tooltips, metadata, counters, badge/status, icons, avatars, circles, pills, dividers, input, focus rings, native controls, links, lists, tables, grids, sheets, dropdowns, empty/loading/error/denied/offline/success. Preserve semantic wording; improve typography, wrapping, alignment, contrast, line length, accessibility and existing localization. Report mistranslations/awkward wording separately; only meaning-preserving orthography/typography corrections with exact before/after and approval if wording changes. AR Egyptian-friendly/standard easy language, DE simple. No rewriting proper names, school data, permissions, financial terminology.
