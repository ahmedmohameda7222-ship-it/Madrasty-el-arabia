# مدرستي العربية · Madrasa Pulse

The iPhone home-screen web app, native Android APK and desktop school office share a visual identity and the same school records. Each platform keeps its own navigation, insets, keyboard, permission prompts and accessibility behavior. The Arabic and German content below is implementation copy for the illustrated scenarios. Names and transfer details in the plates are fictitious.

Show scope and count; open the same filtered queue. More groups staff/application review, delegated access, class/year/subjects, assignments and schedule, attendance and reports, finance, communications, events, school settings and audit as grants allow. |
| Teacher | الرئيسية / Start · الحضور / Anwesenheit · الرسائل / Nachrichten · المزيد / Mehr | Today's assigned class and next lesson; open roster/date or grading in one action. More groups account, directory, language and device settings. |

**iPhone.** Use semantic nested routes and browser history, bottom tabs with labels, grouped lists, hierarchical navigation and a modal selection sheet for child/class. Forward navigation pushes history; Back and the edge gesture restore the previous tab stack, scroll, selection and filter. A sheet includes an accessible close control, focus containment and return focus. Settings follow Safari and standalone viewport changes. Use `viewport-fit=cover` and native safe-area inset values; fixed footers include bottom safe-area padding, and the body reserves their measured height. With the keyboard present, pin the composer to the available visual viewport and the focused field remains scrollable. Safari setup help uses Share → Add to Home Screen → Open as Web App, with a usable ordinary browser sign-in. Offer push opt-in from a user action in installed mode where supported. [Apple installation guide](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/27/ios/27) · [WebKit Home Screen push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

**Android.** Use `Scaffold`, `NavigationBar`, app bars, Material 3 modal bottom sheets and Compose navigation. Use meaningful start-aligned titles and a filled selected navigation indicator. Back dismisses keyboard, sheet/dialog, detail and then returns through the platform back stack in order. Respect gesture and three-button insets, cutouts and IME padding, consuming each inset once. Restore the current scope/filter over rotation or activity recreation. The school HTTPS download page and verified App Links support install, update and invitation continuation; the APK must cover administrative work too. [Material 3 components](https://developer.android.com/develop/ui/compose/designsystems/material3) · [Android window insets](https://developer.android.com/develop/ui/compose/system/insets)

**Desktop web.** At a proposed 960 CSS px content width, move the same four destinations into a navigation rail and expose the authorized secondary links beside it. At smaller widths keep bottom tabs. For roster/import/invoice queues, use a labelled toolbar, sortable columns where supported, and scoped filter chips. At wide widths a selected row may open a detail pane with its own heading. Collapsing to the phone width keeps detail route and filters, converting a dense line to a labelled card. Import preview keeps row identity, source column, conflict and action together; allow a labelled horizontal scroll region for the mapping grid. Desktop keyboard path is navigation → toolbar → rows → detail; Escape closes the top overlay, and saving returns focus to the affected row.

**Shared scope.** Tabs preserve state separately per account and persona. Returning to a gradebook, child, chat search or fee queue restores the last allowed selection. On explicit persona switch/withdrawal/logout, release subscriptions and evict protected cached state before drawing the next frame. A notification or account invite opened from outside checks the current authority and opens its precise permitted detail. A signed-out person can resume a safe destination after authentication. A forbidden deep link returns to an authorized parent with a short localized explanation.

## Loading and interruptions

The F03 surface is a state machine. Screen owners map the transport outcome and permission to exactly one primary state. Show the non-sensitive shell immediately. As proposed shared timings, start a structural skeleton after 180 ms of an unresolved initial read and add a localized “still loading” status after 8 seconds. Cancel both timers on completion, navigation and scope changes. Show a fast result immediately and resolve errors through the real request outcome. Refreshing an already populated area can use a small delayed indicator in place. Mark skeleton elements decorative, announce loading once via polite status, and preserve headings and controls that already have valid data. Skeletons follow the actual list/card geometry. Use static neutral shapes for reduced motion; a subtle short opacity pulse is optional elsewhere.

| State | What the person sees and can do |
|---|---|
| Cold load | Heading and one scoped skeleton group, no sample names, zeros or disabled imitation data. A second skeleton group is useful only for a separately loading area. Never announce every bar. |
| Cached shell with missing data | Immediately show non-sensitive shell chrome and structural skeleton rows. Only render cached student fields where the offline policy explicitly allows a previously opened attendance roster for the exact authorized device partition. On another account/persona clear the whole protected subtree before presenting skeletons. |
| Background refresh / stale | Keep still-permitted content in place, offer a compact activity indicator and last-confirmed time. Show stale or offline state, preserving scroll/focus. If a previous scope is no longer authorized, discard its data before presenting a replacement. |
| Empty / filtered empty | After a successful response use an action relevant to that role. Distinguish “لا توجد نتائج لهذا البحث” / „Keine Treffer für diese Suche“ from an empty first-use roster. Clearing a filter never widens the actor's permissions. |
| Read error / save error | Explain the action that failed, provide retry, retain meaningful input. Initial failure gets a dedicated error region. Failure after a refresh gets a small banner and last-confirmed information only if still permitted. Use separate states for offline, permission revoked and service failure. |
| Pending / success | Label the pending action until server acknowledgment; suppress duplicate submit with an accessible progress state. A confirmed response replaces pending text, updates the exact row, then announces success once. For uncertain writes, reconcile the original idempotency key before offering another submission. |
| Local draft / conflict | In offline attendance show «مسودة على هذا الجهاز» / „Entwurf auf diesem Gerät“ and last sync; no approval. An offline excuse remains unsent. On reconnect merge unaffected rows and focus only the conflicted child, with server vs draft values. A real arrival or locked family report keeps server precedence. |
| Read-only / revoked / device denial | Read-only history shows reason and any allowed correction route. On revoked data access replace visible protected data and focus a generic scope notice with a safe return. On denied mic/photo/push, leave authorized text/other channels available and give actionable device settings help where the OS permits. |

## Language, privacy and assistive technology

- Set web document `lang` and `dir` from UI locale and use logical start/end margins. Compose sets localized layout direction and accessible text. Preserve user-entered names exactly. Wrap mixed strings and codes in isolated runs (`bdi` or equivalent); phone, IBAN, class code, invoice identifier and stable number must copy in original order. Format dates/currency per locale from school-date and minor-unit inputs. Never parse a display string to post a payment.
- Mirror back/forward chevrons, navigation order and directed send glyphs. Maintain the original orientation of a pupil photograph and playback controls. Test both languages on both systems at Q06; the sheets intentionally use one pairing to make their differences visible.
- Delegate photo selection to system photo pickers or an accessible web file input; offer camera only when supported and requested. For audio, request microphone during the record action, show a visual and announced recording state, review and cancel. On interruption stop capture safely and show an unsent review/draft. On iPhone a denied permission can require Safari/system settings; Android may require app settings after a permanent denial. Keep sensitive reasons, grades, bank values and private chat content out of lock-screen previews.
- Label all inputs, buttons, headings, selected tabs, expandable groups, relative status and progress. Associate descriptive errors with fields. In RTL sort the semantic reading order by the content hierarchy, including action after its record. VoiceOver/TalkBack should hear the name, role and state before an action. Announce the copied field, the one locked attendance row or a completed send once. Operation status should not steal focus from typing. Return focus after sheets, attachments and contextual navigation.
- Q06 evidence covers iPhone installed and browser modes, Android install/update, narrow 320 CSS px web width, smallest supported Android width, default and 200% text, portrait/landscape, keyboard open, dark/light, both language directions and a screen reader on each platform. Inspect contrast in actual themes, 44/48 targets, safe-area/IME overlap, state transitions and focus. Final QA is the first phase that authors or runs product tests.
