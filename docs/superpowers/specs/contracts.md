## Chosen boundaries

- One modular Next.js/TypeScript service on Vercel hosts responsive desktop + iOS web and versioned HTTP handlers. A native Kotlin/Jetpack Compose Android client uses the identical API. Share machine-readable contracts and translation keys; keep platform UI/lifecycle native to each surface.
- Supabase supplies PostgreSQL, Auth, private Storage and scheduled work. All school domain reads/writes go through the server's authenticated application boundary. The base URL for both clients is the school's HTTPS origin plus `/api/v1`. Keep a single application database, no tenant switch, no student identity provider accounts. Never let arbitrary app clients select a school or staff persona with greater rights.
- Proposed artifact map adopted by this plan: `apps/web/src/app/api/v1` HTTP; `apps/web/src/server` domain services/policies/adapters; `apps/web/src` web UI; `packages/contracts/src` runtime-validated DTOs and generated OpenAPI; `apps/android/app/src/main/java/de/madrasty/app` Compose app; `supabase/migrations` ordered database changes. Module plans subdivide these landmarks. These are future files; generated timestamps, toolchain versions, signing identity, public hostname, provider credentials and connected project IDs beyond those verified above are F01/D02 bindings. Do not guess them. Reserve one migration writer/integration pass per shared schema. Never rewrite an applied migration.
- Web uses server-managed session in Secure, HttpOnly, SameSite cookies (CSRF token/origin validation on writes). Android uses Supabase Auth PKCE/verified app links and Keystore-backed refresh-token storage, calls domain API with bearer token; no service secret in either client. Validate issuer, audience, expiry, current active user/session, allowed persona and resource scope server-side. User-editable metadata never grants permissions. Admin MFA + recovery; strong reauthentication for bank edits.
- Restrict DB access to private schema `app`; revoke public/default role access; enable RLS and object policies on sensitive relations. Use a non-owner, non-BYPASSRLS runtime SQL role over a pooled connection. Per transaction set local verified actor/session/persona context, never leave it on a pooled connection. The API may request a persona, but the server independently verifies the grant. Policies use effective-dated assignment, active family link, named invoice payer and thread membership as appropriate. Private worker access is scoped to its job. No ordinary DM content in school-wide email history, audit, alerts, exports or log search. Staff inbox delegation grants access to that inbox, not a private predecessor's conversations.
- Supabase Auth admin secret only in restricted server adapter. Private media download/stream always passes a fresh object check; temporary grants expire quickly, never public bucket URLs. Strip image location metadata, validate signature/content/type/size/duration, quarantine failed inputs. Shorten cache lifetimes for sensitive content; never cache complete responses in a shared CDN or service worker. Clear per-persona drafts, caches and device push association on logout/switch/revocation. Retention/restore are explicit release inputs.
- Schedule an authenticated dispatcher (Supabase Cron invoking a protected worker, using a managed secret); retain outbox, recipient status and retry state in Postgres. No assumption that a Vercel request stays alive after replying. Use idempotent provider identifiers where supported, backoff and bounded redrive; label uncertain delivery for reconciliation. Retest eligibility/language at send time; historically issued invoice remains with the named payer. Queue per translated recipient; never expose other recipients in To/CC. Stage with sink/test recipients.

## HTTP and transaction conventions

The authoritative operation inventory lives inside each module's task cards. When binding the OpenAPI file at F02 and extending it per task, give each route one owner and example success + error. Keep exported OpenAPI checked in by the final integration task and generate typed client models from it. Product changes should change both clients together.

| Contract | Convention |
|---|---|
| Resource identities | Opaque UUID for internal objects. Stable human student number (e.g. MA-001284), separate invoice number and source import key. Never authorize by knowledge of a number. School-date YYYY-MM-DD and billing month YYYY-MM; UTC instants for events with school timezone for calendar boundaries. Half-open intervals for effective dates. Monetary values in integer minor units, ISO currency, separate invoice history snapshots. |
| Success | JSON `{data: T, meta?: {nextCursor?: string}}`; 201 create, 200 read/command/replay, 204 where operation documents an empty response. List DTOs use stable sort + scoped cursor, default 25 max 100. Media bodies/CSV have their registered content types. |
| Errors | `{error:{code,messageKey,fields?,requestId}}`; 400 malformed, 401 expired, 403 unauthorized action, 404 concealed/unavailable object, 409 conflict/duplicate payload/stale revision, 422 business validation. 429 throttled, 503 retryable service issue. Field errors localized on both clients. Parent/teacher list counts and search never reveal unrelated records. |
| Safe retries | Financial writes, attendance approval/arrival, publish, invitations, import commit, sends and message upload finalize take an Idempotency-Key scoped to actor, operation and request hash. Before looking up or returning a prior receipt, revalidate current session, persona, grants and object visibility; scope receipt keys by account, active persona and operation. If access was revoked, return the same denial as a fresh request without disclosing a cached DTO or repeating the mutation. Same authorized payload replays prior result, different payload/key reuse returns 409. Audit row, write, revision and event in one transaction. Add DB unique business keys against concurrent independent requests too. |
| Concurrency | Mutable forms carry a revision; stale write returns latest authorized revision/changed fields. Attendance uses row-level revisions/locks so a contact report conflicts only with that child. Offline merge keeps untouched rows, requires a human for changed conflicts, and never sends a false success. Idempotent replay can return success even if old revision is now stale. |
| Outbox | Unique event ID, type, UTC occurredAt, actorId, aggregateId, minimized payload. Unique delivery per source event + channel + recipient. Persist per-user read separately from provider delivery; version/cancel scheduled jobs when source changes. Notification tap authenticates and scopes again before opening the exact resource. |
| File and import | Preserve source metadata only as needed; temporary upload has owner + purpose + expiry. Separate preview, confirmation and invitations, audit counts without family CSV or banking details in logs. Export follows same filters/policies and neutralizes spreadsheet formula cells. |
| Offline | Cache only a minimum authorized roster for previously opened sheet and matching account on this device. Draft keys include persona/class/date/child as applicable. Invalidate expired/revoked cached scopes on reconnect; auto-lock dormant sessions. No alerts, approval, payment or claim of delivery while offline. Parent cannot send a fresh excuse for a nonscheduled date. |

## Authorization examples required by final QA

| Principal | Allowed | Denied or narrowed |
|---|---|---|
| School admin | Assign capabilities, configure school and designated bank; academic/financial administration and audited corrections | Automatic access to private teacher/family chats. Cannot disable the last capable admin or bypass step-up bank confirmation. |
| Student affairs | Family links, applications, effective enrolment and stop requests, official office replies | Payment posting; automatically showing internal guardian reasons to other family members. |
| Academic supervisor | Assignments, published-grade corrections, substitutes, attendance oversight | Finance or unrestricted private messages absent an independent grant. |
| Accountant | Payer name, student number, charge, settlements, receipts and scoped export | Academic details, private excuses, unassigned inboxes; bank change without explicit grant. |
| Teacher / substitute | Assigned class and subject during valid dates; primary or dated delegate with attendance capability for the day | Other class/subject; bulk overwriting excused locks; reading predecessor's private chats. |
| Guardian / payer | Own linked children; account-specific receipts and threads. Individual read and language settings. | Other guardian's private messages; current roster classmates; own-linked but other-payer invoices. Removed link cuts academic access even via stale link. |

## Operational decisions with owners

F01 binds compatible Node/pnpm/Next, JDK/Gradle/AGP/Kotlin and Android SDK versions using supported release documentation and installed tools, records locks/wrapper before dependencies fan out. F02 owns the wire/error/version contract. D02 verifies whether the supplied project is suitable for pre-launch synthetic data; use an existing isolated branch/staging target if it already holds production data. No destructive reset of a remote project. D03 binds verified email domain/SMTP + transactional email provider, push identities (Web Push VAPID / Android FCM), and actual Vercel scope; D04 binds domain, Android app ID, release-signing custody and published update channel. Owner supplies the actual school bank, tariff, authorised staff, retention schedule and distribution countries before live use. Distinguish required technical integrations from go-live facts; use synthetic fixtures for the first full deployment.
