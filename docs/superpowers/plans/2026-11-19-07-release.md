> For agentic workers: Superpowers executing-plans with the final-only QA cadence in PLANS.md. Keep working through ready tasks. This phase builds and deploys, with test authoring/execution deferred to Q01.

**Objective** A protected Vercel instance, real Supabase-backed services, working provider configuration, iPhone install path and a signed downloadable Android build at the same candidate revision. **Architecture** [Contracts](../specs/contracts.md). **Product** [Release surfaces and owner inputs](../specs/product.md). Exact remote target, domain, tool versions and credential bindings are established during execution. Output files below are planned. Capture nonsecret evidence in PROGRESS.md and docs/execution/release.md.

### D01 — Assemble the same release on all three surfaces

**Goal and requirements** R01, R15, R16, R17. **Depends** All F/I/S/A/E/C/B cards delivered, with module owners' proposed route names reconciled. **Scope** Cross-module assembly, deep links and build integrity. Provider provisioning belongs to D02–D04.
**Files / interface** apps/web/src/app/layout.tsx; apps/web/src/app/api/v1; apps/android/app/src/main/java/de/madrasty/app/navigation/SchoolRoutes.kt; packages/contracts/openapi.yaml; docs/execution/release.md. Accept an allowlisted typed resource link carrying resource ID; resolve session, persona, child and current permission before rendering. Generate Android and TypeScript client models from the same contract. Public install pages work before login. Links never contain access tokens beyond single-use authentication flows.
- [ ] Bind every role tab, home queue, detail, notification and contextual contact link to its feature. Name the owner of each endpoint and migration. Confirm the APK has every mobile role flow, including staff, accounting, finance and import.
- [ ] Assemble translation catalogues, illustrations, media controls, release version, loading/error behavior and signed-in account switch. Remove sample identities, demo toggles and browser-only success handlers.
- [ ] Build a candidate, store commit/build identifiers, record contract compatibility for the previous supported APK, and resolve source/build integration failures.
**Expected / final cases** One child's deep link cannot carry the previous child's details; expired or revoked links show recovery/denial. Generated clients match the deployed contract. **DoD** Planned `pnpm check:types`, `pnpm build:web`, `pnpm build:android` exit 0. Record artifacts; behavior remains awaiting Q02–Q06.

### D03 — Deploy web, API, dispatch and device notification integrations

**Goal and requirements** R01, R10–R12, R16, R17. **Depends** D02, correct Vercel team/project or authorization to create a missing one, controlled HTTPS origin and pre-launch provider identities. **Scope** Hosted pre-release deployment and delivery configuration, no live family sends.
**Files / interfaces** apps/web deployment settings; docs/execution/{environment,release}.md; credential names in .env.example. Use the existing outbox worker, Supabase Cron, private webhook, SMTP/transactional provider, Web Push VAPID and Android FCM. D03 and D04 must share one school-controlled final HTTPS app hostname before building the release APK. For pre-launch, bind that hostname to the protected, synthetic-only candidate with a tester access gate that admits both clients; keep install/association files public where required. If the hostname already serves live users, reserve a different school-owned final app hostname or use an explicitly reviewed server-side route for authorized tester identities. Never take over an active production service. The APK pins the school API origin, not a staging backend URL. Retrieve environment-specific public Auth parameters from a school-origin configuration endpoint over TLS, allowlist the expected issuer for that environment server-side, and separate Auth sessions and delivery identities by environment. FCM app identity and release package/signing fingerprint stay compatible across activation. D06 switches the server-side target/gate; no APK repack or secret switch embedded in the client. D03 owns HTTPS origin, D04 owns package/signing metadata. Public association files must be accessible without session where the platform requires it; protect school data separately.
- [ ] Verify connected Vercel scope by repository and owner, bind web root/monorepo dependencies, Node version and target-specific environment. Keep tokens for Supabase, database, provider, FCM and jobs server-only. Bind the verified sender and mail domain records per provider, validate webhook signatures and timestamps, set throttling/redrive and stage recipient restrictions.
- [ ] Deploy the integrated candidate to stable pre-launch HTTPS origin; bind scheduled worker credentials/URL, public manifest/icons, auth callback, privacy-safe logs/alerts. Set no-store on private responses. Keep origin association and APK download working for invited testers on actual devices using target-appropriate access controls.
- [ ] Save deployment ID, source commit, origin, function/worker states, provider configuration and limits, and references to secret owners. Incomplete credentials mark integration pending. Continue independent tasks without substituting fake success.
**Expected / final cases** Signed-in and out deep links have defined landings, denied push still has inbox/email, cron failures remain observable. **DoD** Vercel reports Ready for recorded revision, provider and scheduler configuration captured. Q05/Q07 verify real end-to-end delivery to controlled recipients.

### D04 — Package native Android and publish the iPhone install path

**Goal and requirements** R01, R15, R17. **Depends** D02, D01 Android build and origin agreement with D03; once agreed build/sign can run alongside D03. **Scope** Install, release signing, version discovery and update compatibility. No change to school enrollment.
**Files / interfaces** apps/android/app/build.gradle.kts, apps/android/app/src/main/AndroidManifest.xml, apps/web/public/.well-known/assetlinks.json, apps/web/public/manifest.webmanifest, apps/web/src/app/install/page.tsx, apps/web/src/app/download/android/route.ts, docs/execution/release.md. Propose GET /api/v1/client-versions returning data with minimum/suggested Android version code and allowlisted HTTPS download path. GET /download/android resolves the currently authorized APK. Never host the private key in Git. Use an artifact store able to serve the confirmed file size.
- [ ] Record permanent app ID, school-owned signing/key-backup custodian, version code/name, intended distribution regions and applicable signing/verification inputs. Sign using protected key access. Create release artifact and SHA-256, record public certificate fingerprint and package ID.
- [ ] Publish Android version/download/upgrade path and install instructions; support verified app links and web fallback. Serve school-hosted iPhone Add to Home Screen instructions with standalone manifest/icons, safe area and user-triggered push permission. Keep web login available throughout installation.
- [ ] Retain a prior compatible release or build a lower-version baseline with the same permanent package ID, release signer and school origin as the candidate. Restrict tester distribution for this baseline. A debug or separately signed staging app cannot prove in-place upgrade of the release APK. Preserve production key custody and minimum-API backward compatibility. Record sizes/URLs and signing tool output.
**Expected / final cases** Updated APK with same ID+signer can replace earlier install; untrusted download, unsupported build and disabled permission produce useful actions. **DoD** Signed release artifact and association/download files recorded; `apksigner verify --print-certs <actual-apk>` returns the recorded certificate and exit 0 (artifact integrity). Real installs and updates run in Q06.
