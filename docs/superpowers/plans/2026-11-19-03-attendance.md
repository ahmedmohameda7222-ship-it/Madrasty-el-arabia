# Daily attendance and family excuses implementation plan

> Use Superpowers executing-plans and the common definition of done in PLANS.md. The acceptance cases are specifications for final QA (Q03–Q05 and device checks) after the full pre-launch deployment. Do not write or run tests during these cards.

**Goal** Give a family and its child's assigned attendance teacher one consistent school-day record, including when connectivity or timing differs across devices. **Architecture** Next/Vercel API transactions against private Supabase Postgres with RLS, web PWA and native Kotlin/Compose clients. Read the [product](../specs/product.md) and [integration contracts](../specs/contracts.md).

**Files and constraints** F01 binds repository paths and build commands. New planned files use `packages/contracts/src/attendance/<stem>.ts`, `apps/web/src/server/attendance/<stem>.ts`, `apps/web/src/features/attendance/<stem>.tsx`, and `apps/android/app/src/main/java/de/madrasty/app/attendance/<Screen>.kt`. Add the corresponding `apps/web/src/app/api/v1` route handlers and ordered `supabase/migrations` files for each named SQL suffix. The URL prefix below is `/api/v1`; JSON envelopes, error semantics and idempotency follow F02. School dates use S01 and the as-of class roster uses S03. Both clients use F03 translations, focus, offline/error/status affordances and visible child/class/date context. A committed event is inserted into the private outbox in the same SQL transaction; external delivery belongs to communications. Review each card by source inspection and F01's type/web/Android builds only; record results in PROGRESS.md.

**Review focus** Cancelled dates, a family report arriving in an open sheet, a stale bulk action, real arrival racing a new excuse, and sharing/signing out of an offline device.

### A01 — Open, mark and approve one daily class sheet

**Goal / requirements** R06. Differentiate a saved teacher draft from a complete approved day. **Depends** S01, S03, S05, F02, F03. **Files** `sheets`, `DailySheetScreen`, migration `attendance_sheets`. **Scope** Primary class teacher or authorized dated substitute marks; supervisor oversees/corrects under separate authorization. Other subject teachers receive no write capability.
- [ ] Add sheet (UUID, class/year FK, school_date date, open/approved state, roster_revision, approval_revision, approval actor/time; unique class/date), rows (UUID, sheet/student/enrollment FKs, status nullable enum present/late/absent_unexcused/absent_excused, revision bigint, lock source, confirmed arrival actor/time), unique sheet/student and student/day as a cross-class guard. Capture class and enrollment that applied that day; revalidate roster before approval. A null status is unmarked. Initialize an eligible sheet/rows via idempotent command; finalized history retains its original roster. School cancellation prohibits marking/approval and invalidates obsolete pending alerts.
- [ ] Implement `GET /attendance/classes/{classId}/days/{date}` → scoped sheet view including roster/row versions or eligible unstarted, `POST /attendance/classes/{classId}/days/{date}/open` → active sheet; `PATCH /attendance/sheets/{id}/rows` {edits:[{rowId,revision,status}]} → saved rows and row-specific conflicts; `POST /attendance/sheets/{id}/mark-present` {rows:[{rowId,revision}]} → applied, skippedLocked, conflicts. Process compatible edits in one transaction with per-row outcomes (200 with lists for mixed batch); ensure each write predicates on open state and current row version. Never rewrite a locked excuse row, even from an old open sheet. Resolve conflicts using current authorized DTO only. Save ordinary drafts without issuing unexcused-absence events.
- [ ] Implement `POST /attendance/sheets/{id}/approve` {approvalRevision,expectedRows:[{rowId,revision}]} → approved revision, counts and timestamp. Lock sheet then rows in stable order, re-evaluate roster, day, actor and completeness. Reject changed rows with 409 and unmarked roster with 422. Atomically save approval/audit plus `attendance.unexcused_confirmed` once per approved unexcused child/revision; clients pass Idempotency-Key. Skip excused/late/present for this event. Same-input retry returns original receipt.
- [ ] Build teacher's Attendance tab (assigned class, date, all four labels, unmarked count, explicit bulk present, save draft, reachable separate approval action) and supervisor pending sheet list on both clients. Include approved/read-only and cancelled-day states; refresh stale roster without overwriting unrelated edits.

**Acceptance at final QA** Adjacent lessons in one class/day share one sheet. A timeout/retry or two concurrent approvals yield one receipt/event per eligible absence; an unrelated subject teacher cannot submit. Null prevents approval and a closure between open and save returns closed-day feedback. **DoD** Inspect DB constraints and transaction order, denial paths, row-only conflicts and both approval controls; record builds.

### A02 — Receive a parent's excuse and resolve actual arrival

**Goal / requirements** R06. A parent's scheduled-day reason reaches an already open sheet, locks that child, and can be superseded only by recorded actual arrival or a valid withdrawal. **Depends** A01, S02. **Files** `excuses`, `FamilyExcuseScreen`, migration `family_excuses`. **Scope** Linked guardian reports; authorized attendance staff see the private reason. Only the reporting guardian withdraws their active report before approval/arrival; another guardian receives only information authorized for that child.
- [ ] Add private excuse (UUID, child/date, reporter, private reason text, pending/withdrawn/superseded state, timestamps, revision); allow one active report per child/date, retain history. Use A01's consistent sheet→row lock order in all paths. On receipt check active link, effective enrollment and teaching date, materialize eligible sheet/row if unopened, check approval and actual-arrival fact, write reason, set excused/locked, increment row revision. Retain prior pending status for valid withdrawal or restore unmarked if none. Never resurrect a prior actual arrival or merge two guardians' private explanations.
- [ ] Implement `POST /children/{childId}/attendance/excuses` {schoolDate,reason} → confirmed receipt/rowRevision; `POST /children/{childId}/attendance/excuses/{id}/withdraw` {revision} → withdrawn/unlocked pending row; `POST /attendance/rows/{rowId}/confirm-arrival` {revision,status:present|late,confirm:true} → recorded actual arrival + unlocked status. Explicit confirmation is one atomic command; no reusable free-edit unlock. Store arrival evidence separately from provisional bulk-present. Once arrival commits, ordinary drafts, withdrawal or excuses cannot change it back to absence. If an excuse wins the race, the staff arrival dialog refreshes the one row, reaffirms the intended arrival and retries with its current revision. After approval use A04.
- [ ] Build parent child-card excuse form/receipt/withdrawal, including separate draft/confirmed state. On both teacher platforms show protected reason and lock only in scoped row detail, explain bulk skip and require deliberate present/late actual-arrival confirmation. Emit `attendance.arrival_confirmed` with child/date/record/revision and no reason for guardians once. Restrict reason access to submitting guardian and assigned authorized staff/supervisor; exclude free text from generic response logs, exports, events, notifications, caches and lock screens.
- [ ] Push row invalidations to scoped online sheets through an authenticated API stream or private Realtime topic allowed by F02; publish only sheet/row ID and revision. Refetch scoped row via API on invalidation, reconnect and foreground; fallback to short conditional polling. Close subscription on scope loss. Update locked row without resetting other unsaved changes. Response to an outdated client/race always reports the current row and resolution.

**Acceptance at final QA** Report from iPhone while Android sheet is open; teacher sees reason and lock, a stale bulk action skips the child, siblings stay unchanged. Withdraw before approval and verify reopening; after actual late arrival a competing report/withdrawal cannot reverse it. Repeating a submission returns the initial receipt. A non-school date, closed sheet, revoked guardian and expired substitute all receive explicit scoped outcomes. **DoD** Inspect lock ordering, stream authorization/reload, reason redaction and both confirmation flows; record builds.

### A03 — Keep unsent attendance drafts safely on each device

**Goal / requirements** R06, R15. Support real offline marking of a previously cached class/day, preserve edits through navigation, and reconcile only conflicting rows. **Depends** A01, A02, F03. **Files** `draft-sync`, `OfflineAttendanceScreen`; planned web `attendance/draft-store.ts` inside the feature and Android `attendance/AttendanceDraftStore.kt`. **Scope** Attendance-only local storage; approval and actual arrival require server acknowledgment.
- [ ] Implement per-device private storage with minimal class roster/row IDs, allowed status, lock flags and base revisions keyed by account/session lineage/persona/class/date and expiring scope. PWA uses IndexedDB with session-bound protection and persistence according to F02; native uses app-private DB with Keystore-protected material. Store local edits separately from remote baseline and exclude medical reasons from teacher roster cache. Keep unsent parent text in a separate protected, expiring per-parent/child/date draft. Warn before logout with unsent changes; purge on confirmed logout, scope revocation, expired session or persona switch, and reset device push linkage with Identity.
- [ ] On both clients indicate cached-baseline time, offline availability and unsent count; opening an uncached class/date cannot fabricate a roster. Keep draft through navigation/app restart within the valid authenticated scope. Parent sees “not sent” until explicit send obtains A02's server receipt. A parent returning online reviews/sends, with day/link/arrival revalidation. Disable approval/arrival offline; do not queue automatic confirmations.
- [ ] On teacher reconnect fetch the current sheet, date eligibility and authorization before applying pending edits. Compare base vs current per row; send safe differences using A01's edits with row CAS/idempotency, clear acknowledged/equivalent edits only. Show fresh server value and local proposal for each conflicted student; retain all unrelated changes, offer keep-server or explicitly reapply an eligible edit (locked excuses require A02). If the server approved/cancelled the sheet, keep it read-only and explain discarded/ineligible edits. Expired authorization removes cached private data.
- [ ] Register web foreground/network-change and Android process resume/connectivity paths with the same deterministic merge. Persist in-flight request key + selection for a timeout retry; a response lost after server commit cannot create a second change.

**Acceptance at final QA** Cache class A/day 1, lose network, mark three rows, restart, then reconnect after a parent excuses one child. Two rows save, one needs resolution, no data appears in another account/class/date. Parent draft with unsent text sends no event and may be declined if the school day was cancelled. **DoD** Inspect minimal stored fields, cleanup paths, merge and both clients' receipt labels; record builds.

### A04 — Attendance history, audited correction and alert reconciliation

**Goal / requirements** R06. Guardians and staff read authorized finalized history; changes to an approved day update the record and correct any communications. **Depends** A01, A02, S02, F02. **Files** `history`, `AttendanceHistoryScreen`, migration `attendance_corrections`. **Scope** School owns facts and correction events, communications owns channels/delivery ledger.
- [ ] Add immutable approved row revision/correction history (row ID, old/new status, actor, UTC instant, private correction justification, predecessor revision). Implement `POST /attendance/rows/{rowId}/corrections` {revision,status,reason} → new approved revision/receipt. Require supervised correction authority, nonblank reason, different state, open-to-correction year policy and current approved revision. Updating a finalized day preserves original approved by/when. A cancelled-day correction uses supervised handling for affected committed history and cancels obsolete absence jobs; never emit an absence about a cancelled school day.
- [ ] In the same transaction emit `attendance.corrected` carrying child, class/date, prior/new approved status, aggregate/revision, prior event reference; no private explanation. A change into unexcused absence schedules the standard currently-required alert once via communications; a change out cancels pending absence jobs and generates corrected notices only for eligible recipients who received the superseded notice. Job dispatch rechecks current link, date and record revision. Initial approved unexcused absence drives one replyable system message, in-app alert and localized email per eligible guardian through C07.
- [ ] Implement `GET /children/{childId}/attendance?from=…&to=…&cursor=…` → school's dated approved statuses/class history; include the reporting guardian's provisional excuse receipt via separate A02 read fields, clearly labeled. Implement scoped `GET /attendance/rows/{rowId}/history` → staff-only source/correction revisions. Support date range, status filters for staff, parent child switching, empty history and supervised correction preview on web/Compose. Protect lists, deep links and counts against revoked access.
- [ ] Expose approved-only counts by child/class/date and status to E07 plus pending-sheet count/drill-down to D01. Keep unmarked or cancelled dates out of absent totals. Do not return reasons from aggregate/report reads.

**Acceptance at final QA** On-schedule unexcused absence confirms then corrects to present before/after communications dispatch; pending alerts cancel or recipients get one correction according to delivery status. Parent/teacher with revoked scope cannot read history via an old direct link. Report totals show the latest revision and old staff audit still explains the change. **DoD** Inspect privacy projection, approved count queries, dedupe rules and both clients' read/correction paths; record builds.
