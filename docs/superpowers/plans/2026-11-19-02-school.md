# School records and operations implementation plan

> Use Superpowers executing-plans. Follow the execution order and common definition of done in PLANS.md. The acceptance cases below are specifications for final QA starting at Q01.

**Goal** Give student affairs and academic supervisors a dependable record of who attends, who may act for each child, who teaches each class, and when. **Architecture** Next.js on Vercel, private Supabase Postgres with RLS, responsive PWA and native Kotlin/Compose clients. Read the [product](../specs/product.md) and [integration contracts](../specs/contracts.md) before implementation.

**Global constraints and files** F01 binds paths and commands to the real checkout. These are adopted new paths. For each named file stem below, use `packages/contracts/src/school/<stem>.ts` for wire types, `apps/web/src/server/school/<stem>.ts` for transactions, `apps/web/src/features/school/<stem>.tsx` for web, and `apps/android/app/src/main/java/de/madrasty/app/school/<Screen>.kt` for Compose. Put handlers for the listed URLs under `apps/web/src/app/api/v1` and new ordered SQL under `supabase/migrations`. Routes below omit the shared `/api/v1` prefix and JSON success/error wrappers. Use CAS revisions and Idempotency-Key for commands. Verify each card with static inspection and F01's type/web/Android builds only. Write and run tests only after the integrated pre-launch deploy at final QA. Record build evidence and outstanding integration links in PROGRESS.md.

**Review focus** Same-name pupils, revoked links in repeated imports, local-day transfers, teacher authority at interval boundaries, and simultaneous timetable edits. The checklist in each task covers web and APK. Use F03 Arabic/German labels, input errors, accessible status, read-only states and mobile layouts throughout.

### S01 — School settings, school years and teaching days

**Goal / requirements** R05. Give administrators control over the year, school-local dates and calendar exceptions. **Depends** F01, F02, F03, I03. **Files** `calendar`, `CalendarScreen`, migration suffix `school_calendar`. **Scope** Operative calendar and school settings. Communications owns published monthly events and finance owns bank/tariff.
- [x] Create `school_settings(timezone text, name_ar text, name_de text, currency char(3), due_day smallint, revision bigint)`, `school_year(id uuid, starts_on date, ends_exclusive date, teaching_weekdays smallint[], state, revision)` with non-overlapping date ranges, and `day_exception(year_id, class_id?, school_date, teaching boolean, reason, revision)`. Enforce one school-wide or class override per date/scope including null scope. Reserve the nullable class UUID here; S03 adds its foreign key after creating classes. Until then scoped exception writes cannot reference a class. Validate IANA zone, ordered boundaries, weekday values and due-day bounds. Resolve short-month due day using finance's documented month-end rule.
- [x] Implement `GET/PATCH /school/settings`, `GET/POST /school/years`, `PATCH /school/years/{id}`, `PUT /school/years/{id}/days/{date}` with classId optional, teaching, reason and revision. Return saved settings/year/day plus revision. Expose shared `is_teaching_day(class_id,date)` using class exception, school exception, then year weekday; outside-year dates false. Recheck permissions, reject contradictory changes to approved records or route them through supervised correction.
- [x] Build year/settings editor and class-day exceptions on both clients. Show timezone, closed/cancelled reason and effective date on relevant views. Keep closed-year records readable.

**Acceptance at final QA** A school closure blocks both classes; an explicit class teaching override affects only that class. A cancelled day cannot create or approve a sheet or alert. A school-local date near midnight stays identical across platforms. Invalid zone/overlap returns field errors. **DoD** Inspect the date resolver shared by attendance and schedules, SQL constraints and both screen bindings; record successful builds.

### S02 — Create families and pupils, review guardian relationships

**Goal / requirements** R04, R05. Establish one durable student number and approved child links, including siblings and multiple guardians. **Depends** F02, F03, S01. **Files** `families`, `FamiliesScreen`, migration `families_links`. **Scope** Student affairs/admin manages family records and relationships; Identity owns Auth accounts, canonical recipient binding and invites.
- [x] Create pupil (UUID, immutable unique student number, school/source child key, name, state), guardian profile (UUID, unique stable source guardian key, contact, preferred communications locale, optional identity binding), and link history with unique active guardian/pupil pair, pending/approved/revoked state, effective instants, actor and revision. Preserve revoked tombstones. Allocate student numbers atomically; enforce unique source namespace + external key. Similar names or a shared contact never suffice for a merge. Approval for an existing activated guardian emits one private `family.link_approved` per new link revision; revoke access and pending deliveries on unlink. Preserve billed-to invoice access by independent payer ID.
- [x] Implement scoped `GET/POST /school/students`, `GET/PATCH /school/students/{id}`, `GET/POST /school/guardians`, `GET/PATCH /school/guardians/{id}`, `POST /school/guardian-links` with guardianId/studentId → pending, and `POST /school/guardian-links/{id}/{approve|revoke}` with revision/reason → link/revision. Permit initial admin manual create+approve transaction after explicit confirmation. Delegate activated-email changes to Identity verification. `GET /me/children` returns only approved child summaries of the active family persona.
- [x] Build list/search by name or stable number, child detail, guardian detail/links, approve/revoke confirmations and parent child switcher on web and APK. Re-scope child data on every switch, link change and direct URL; conceal other families from queries, counts, detail and outstanding caches.

**Acceptance at final QA** Two pupils named alike retain independent numbers; two guardians may link to a pupil; one guardian may see two siblings. Revocation hides the child immediately after server acknowledgement; billing receipts for an already named payer remain scoped. Pressing approve twice produces one relationship/event. **DoD** Inspect active-link RLS, uniqueness, history, invitation boundary and both clients; record builds.

### S03 — Effective enrollment, transfers and year-end rollover

**Goal / requirements** R05. Seat students individually or in bulk, preserve historical rosters and close a year with reviewed exceptions. **Depends** S01, S02. **Files** `enrollments`, `EnrollmentScreen`, migration `effective_enrollment`. **Scope** Student affairs writes school membership; finance uses the effective dates when approving a stop.
- [ ] Add classes (UUID, year FK, stable code, localized name, optional capacity, unique year/code), enrollment (student/class/year FK, effective `daterange [)`, revision, ending reason). Install the deferred FK for S01 class-specific day exceptions. Exclude overlapping primary ranges per student/year, enforce same year/class, calendar boundaries and capacity under serialized class locks. Expose `roster_on(class_id,date)` and `class_for_student(student_id,date)`. Keep a transaction-safe school membership mutation for finance stops with bounded pauses/resumption and open withdrawals (B05). A write to membership also invokes E03's future roster-insertion hook in the same transaction once installed.
- [ ] Implement `GET/POST /school/classes`, `GET/PATCH /school/classes/{id}`, `GET /school/classes/{id}/roster?date=…`, `POST /school/classes/{id}/enrollments` {studentIds,from,revision}, `POST /school/enrollments/{id}/{transfer|withdraw}` {effectiveDate,toClassId?,reason,revision}. Return affected periods, before/after classes and revisions. Accept a valid school-local effective date; for a same-day change with a committed record, preserve its historical class and show the impacted records for supervised resolution. Preserve prior attendance/grades. Lock both affected classes consistently and handle concurrent seats atomically.
- [ ] Add `POST /school/years/{id}/rollovers/preview` {targetYearId,classMap,exceptions} → plan ID, counts, per-child action/conflict and source revisions; `POST /school/rollovers/{id}/confirm` {revision} validates the same snapshot, explicit repeat/withdraw/skip/target overrides and capacity. Write once or roll back. Existing target enrollment is a conflict or identical replay.
- [ ] Build editable class directory, capacity/roster, date-effective bulk placement/transfer, school-leaving history and rollover preview/confirmation on both clients; distinguish historical from upcoming placement.

**Acceptance at final QA** Moving a pupil tomorrow leaves yesterday's class and records intact; overlapping or full target refuses without losing their original seat. Competing/repeated rollovers cannot double-enroll a child. Bounded stop ends and resumes only the requested child's membership. **DoD** Inspect range constraints, transaction order, as-of reads and both preview screens; record builds.

### S04 — Preview, resolve and commit CSV/XLSX family imports

**Goal / requirements** R04. Turn one file row per guardian/child relationship into approved, traceable records, separate from sending invitations. **Depends** S02, S03. **Files** `imports`, `ImportScreen`, migration `family_imports`. **Scope** Student affairs/admin only. Both clients use the same parser, mapping and validation on the server.
- [ ] Persist private import job (UUID, owner, source hash, expiry, state, version), normalized rows with row number, stable source keys, typed fields, per-row disposition/decision and reviewed version. Parse bounded CSV/XLSX in a restricted reader, as text where identity matters (leading zeros); accept UTF-8 BOM, quoted delimiters and Arabic/German names. Reject unsupported workbook structures, formulas in identifiers, oversized/decompression-limit files and ambiguous mapping with actionable errors; never execute spreadsheet expressions or log row contents.
- [ ] Implement `POST /school/family-imports` (private, expiring file upload/reference with mime and size), `PUT /school/family-imports/{id}/mapping` {columnMap,worksheet?,delimiter?,revision}, `GET /school/family-imports/{id}/preview` → new/existing/duplicate/conflict/revoked/skipped rows + reason and totals; `PATCH /school/family-imports/{id}/decisions` {rows:[{rowNo,decision,matchedId?}],revision}. Require unique child number or approved source child key, guardian stable key or explicitly resolved profile, and requested link; a conflicting existing/revoked relationship needs explicit review. A re-import alone never restores a revoked link.
- [ ] `POST /school/family-imports/{id}/commit` {reviewedRevision} locks and revalidates records and decisions, atomically applies only approved items, saves stable import receipt and pagination over committed eligible guardian IDs. Unresolved rows block approval unless explicitly skipped. Identical repeated files/requests map to existing business keys, including across jobs; independent changes invalidate a stale preview. Do not create Auth users/send invitations as a commit side effect. Identity's distinct invitation approval screen receives these committed IDs with their eligibility/status; activated guardians with newly approved links get the S02 event once.
- [ ] Build file picker, column mapping, row-level decision list, counts, confirm/replay receipt, link to separate invitation review on web/Compose. Support narrow screens and cancelled file selection. Protect preview reads with the same delegation as writes.


**Operator template** Supply a downloadable UTF-8 CSV and equivalent XLSX from the import screen (one relationship per row). Preview lets staff map localized headings, select a worksheet and verify both stable external keys and locale. Blank studentNumber means allocate once from the child key. A repeated child must agree on its identity fields. Illustrative rows:

```csv
childKey,studentNumber,childName,guardianKey,guardianName,email,communicationLocale,payerCandidate
C-301,,Salma Example,G-17,Nora Example,nora@example.invalid,ar,yes
C-302,,Omar Example,G-17,Nora Example,nora@example.invalid,ar,yes
C-301,,Salma Example,G-19,Jan Example,jan@example.invalid,de,no
```

A payer candidate is a proposed billing designation for this child. Show conflicting/missing designations in review and pass only the approved payer relationship to Finance. Importing an additional guardian alone cannot replace an existing payer or modify issued invoices.

**Acceptance at final QA** Import an XLSX with two siblings/two guardians and a name collision, then equivalent CSV. Preserve leading zeros, both sibling links and a previously revoked unrelated link; no duplicate people, invites or school numbers. A second admin edit between preview and commit returns conflict and saves nothing. **DoD** Inspect parser limits, unique/revision checks, absence of invitation dispatch in commit and both pickers; record builds.

### S05 — Staff profiles, class teachers and scoped assignments

**Goal / requirements** R05. Establish who is responsible for a class's attendance and which teachers, substitutes and office staff are eligible for each operation/contact. **Depends** S01, S02, S03. **Files** `assignments`, `StaffAssignmentsScreen`, migration `staff_assignments`. **Scope** School owns professional profile and assignment data; Identity owns login/persona grants; I06 owns directory list, search and profile reads; C01 owns starting or resuming a conversation.
- [ ] Add staff profile (person UUID, professional name/title/email, optional work phone, active interval); minimal subject table with stable keys FIQH/SEERAH/HADITH and localized names for E01; class-subject offering with unique class/subject; effective assignments with teacher, primary-attendance or subject-teacher kind, date range, revocable capability set; and dated substitute delegation scoped to assignment, range and permitted actions. Exclude overlapping primary responsibility for each class, enforce bounded substitute period/authority. Admin editors grant only delegable permissions. Preserve prior periods on replacement.
- [ ] Implement scoped `GET/POST /school/staff`, `GET/PATCH /school/staff/{id}`, `GET/POST /school/classes/{id}/assignments`, `PATCH /school/assignments/{id}` and `POST /school/assignments/{id}/substitutes` {staffId,from,untilExclusive,capabilities,revision} → saved interval, scope, revision. Use shared SQL helpers for date-specific class/subject/operation rights; attendance needs primary responsibility or active delegate plus attendance capability. Ordinary subject teaching alone cannot approve attendance.
- [ ] Expose server-side eligible directory candidates by active persona: all active professional admin staff including principal/deputy; parents see teachers of their linked children's current classes deduplicated; teachers see authorized family contacts in their active classes; admin list respects delegation. I06 consumes this candidate projection; C01 checks chat eligibility and route, and access is rechecked on each read/action. Never expose family members to other parents or return unneeded private phone/email. Build staff/class assignments, permissions and substitute dates editors, read-only staff teaching overview on web and Compose.

**Acceptance at final QA** One instructor teaches two classes with distinct permissions; a substitute loses access at the exclusive end and cannot open old family chats. A child switching class changes eligible teachers. Accounts staff without academic grant cannot read a child's academic record. **DoD** Inspect shared policy calls, dated uniqueness and both editors, then record builds.

### S06 — Generate and edit a collision-safe weekly timetable

**Goal / requirements** R05. Place effective assigned teachers in real class/room slots and show one relevant schedule to each user. **Depends** S01, S03, S05. **Files** `timetable`, `TimetableScreen`, migration `weekly_timetable`. **Scope** Weekly teaching schedule; monthly news/events belong to communications.
- [ ] Add room (UUID, normalized unique code) and weekly lesson slot (class, offering, teacher, room FK, ISO weekday, local start/end minute, effective dates, revision). Validate nonempty half-open minute and effective ranges, assigned teacher/class/subject covering scheduled dates, and school year. Enforce concurrent overlap protection at database level for class, teacher and room across matching weekday, overlapping effective dates and minutes (GiST exclusion constraints or equivalent serialized resource checks); adjacent endpoints are valid. Project local dates using S01 closures.
- [ ] Implement `POST /school/timetable/preview` {yearId,slots:[{assignmentId,weekday,start,end,roomId,from,untilExclusive}]} → proposed generation from assignments with per-field clashes; `POST /school/timetable` with reviewed slots/revisions → atomic saved IDs or scoped 409 conflicts; `PATCH /school/timetable/{id}` and `GET /school/timetable?weekOf=…&classId=…&childId=…`. Enforce scope on list/detail and recheck conflicts at write; return localized subject/class, room and times.
- [ ] Implement admin generation/edit, teacher schedule and linked-child weekly schedule on both platforms including date/week switch, substitute/holiday labels, overlap explanations and empty weeks.

**Acceptance at final QA** Independent requests for the same teacher/room/class cannot both commit an overlap. Consecutive lessons and nonoverlapping effective weeks can coexist. Switching siblings shows their own weeks, including an empty week. **DoD** Inspect constraints, scoped schedule projections and platform date controls; record builds.

### S07 — Route role dashboards to authorized school work

**Goal / requirements** R05. Staff see counted tasks they can act on; teachers and parents open their own classes/children. **Depends** S02, S03, S04, S05, S06, F03. **Files** `work-queues`, `SchoolHomeScreen`. **Scope** School queues/counts and authorized drill-down; D01 composes the attendance, invitation, communications and finance sources after those modules exist.
- [ ] Expose `GET /school/work-queues?asOf=…` → authorized queue keys, counts, filter parameters and routes. Implement `GET /school/work-queues/{key}?cursor=…` for pending guardian links, unresolved imports and classes missing effective primary/subject assignments. Compute counts/list from the same scoped query. Route dated teacher assignments, today's timetable and parent child cards from existing school reads. Hide unimplemented module queues until D01 supplies their source.
- [ ] Add F03 role-home modules in both clients; staff counts open matching actionable records. Preserve active date/filter on back navigation. Support empty/expired assignments, multiple delegated admin roles and revoked access; recheck server authorization for every deep link.
- [ ] Register explicit D01 composition slots for bounced invites, unapproved attendance, noncontinuation requests, settlement review and failed deliveries. The owning service supplies scoped count and filtered destination; a service failure displays unavailable independently of an empty queue.

**Acceptance at final QA** Supervisor and student affairs see different pending workloads; filters agree with counts; teacher/parent persona switch invalidates previous selections. D01 full home drills from each visible queue into the associated real case. **DoD** Inspect query reuse, role switch invalidation, routes on both clients and D01 slots; record builds.

### S08 — Administrative audit and settings navigation

**Goal / requirements** R03, R05, R16. Give designated staff a searchable record of consequential changes and clear routes to the settings they may manage. **Depends** F02, I02, I03, S05. **Scope** Read-only audit metadata and settings entry points on web and Android. Feature owners retain financial receipts, private messages, student notes and approval forms.
**Files** Planned `packages/contracts/src/school/audit.ts`, `apps/web/src/server/school/audit.ts`, `apps/web/src/app/api/v1/school/audit/route.ts`, `apps/web/src/features/school/Audit.tsx`, `apps/android/app/src/main/java/de/madrasty/app/school/AuditScreen.kt`. Extend the audit index via a new migration only if F02's scheme needs a date/actor/action lookup.
**Contract** `GET /school/audit?from=&to=&action=&actorId=&cursor=` → cursor page of {id,occurredAt,actorDisplay,action,resourceKind,permittedResourceLink?,changeCategory,requestId}. Require `audit.read` plus applicable resource category; suppress identifying metadata/counts for out-of-scope resources. The audit store accepts only transactional server events; no user append/update/delete route. Expose reason category when authorized, not private reasons, message text, mail tokens, medical notes or bank values.
- [ ] Map mutations in each module to non-sensitive audit actions and filter family data consistently at the server. Preserve precise correction reasons in the relevant protected domain record.
- [ ] Build scoped time range/search and cursor-paged list, detail navigation and access-loss handling. Group school settings, staff grants, notifications, finance and recovery paths behind their own action grants. Hide destinations without a grant and validate direct links independently.
- [ ] Add school/admin-only summary filters and appropriate zero/error states. Confirm admin role does not imply private conversation access via this view.
**Acceptance / final cases** Grant change, transfer, attendance correction and payment reversal can be traced to an actor/time; finance-only staff cannot retrieve academic history or private DM content through a filter, count or direct link. **DoD** Inspect payload allowlist, grant/query filters and both screen bindings; F01 type and client builds exit 0. Q02 and Q03 verify allowed/denied audit cases on the deployed candidate.
