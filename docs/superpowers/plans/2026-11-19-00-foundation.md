# Product foundation implementation plan

> For agentic workers: use Superpowers executing-plans, with the owner's final-only QA cadence in PLANS.md. Work through ready tasks without requesting routine approval.

**Goal** Establish a buildable boundary between a Vercel web/API service, Supabase and a native Android client. **Architecture/stack** Next/TypeScript, PostgreSQL/Auth/private Storage and Kotlin/Compose. **Spec** [product](../specs/product.md), [integration contracts](../specs/contracts.md), [UI](../specs/ui.md). Requirements R01, R15–R18 are indexed in the traceability matrix.

**Global constraints** One school, one shared API, Arabic and German, authenticated role scopes, offline drafts only. The whole build is deployed with synthetic data before the first QA suite is written/run. This applies to all module cards.
**Review focus** Remote project reuse, pool session leakage, duplicate commands, stale child context, unavailable network and large localized UI.

### F01 — Bind the real workspace and produce reproducible toolchains

**Goal / requirements** R16, R18. Establish a reproducible build and record the operational inputs a fresh machine needs. **Depends** owner-approved implementation plan in a checkout containing this packet. The remote link alone does not contain unpushed local documents.
**Scope** Only toolchains, workspaces, configuration boundaries and execution manifest. No feature screen, cloud resource creation or tests here.
**Files** Modify PROGRESS.md; planned root package.json, pnpm-workspace.yaml, pnpm-lock.yaml, .gitignore, .env.example, apps/web/package.json, apps/android/settings.gradle.kts, apps/android/build.gradle.kts, apps/android/app/build.gradle.kts, generated Android wrapper and version catalog, packages/contracts/package.json. Put version/tool/hosting bindings in docs/execution/environment.md. Exact generated wrapper internals come from the selected toolchain.
**Interfaces** Monorepo builds produce a Next deployable and Android debug/release artifacts. Reserve pnpm root script names `build:web`, `build:android` (calls checked-in wrapper), `check:types`; each is a build/static command, never a test runner. Reserve final QA commands defined below. Inject secrets via server environment; document names, purpose and scope, never values.
- [ ] Run `git status --short --branch`, `git remote -v`, `git ls-tree -r --name-only HEAD`. Read PLANS/PROGRESS and detect existing work. Inventory package managers, Android SDK/JDK, Vercel and Supabase connector scopes; classify the supplied target read-only.
- [ ] Select the compatible supported stable versions from official compatibility matrices, pin and record resolved Node/pnpm/Next, SDK/JDK/AGP/Kotlin/Gradle. Bind a unique Android applicationId owned by the school and final web origins before issuing signed App Links; internal Java namespace is de.madrasty.app. Record unresolved external values independently. Continue local work with test-only origins if production values are unavailable.
- [ ] Create the smallest web/Android builds and contract package, lockfile and wrappers. Record workspace-relative commands for Windows and Linux counterparts using the wrapper. Record build paths and supported OS/browser floors (proposed iOS 16.4+, Android 8/API 26+, target current supported Android SDK after compatibility check).
**Acceptance / final cases** Clean authorized checkout recreates both artifacts without private credentials in client bundles; missing live inputs are documented. Native distribution uses stable package identity, supporting future update. **Checkpoint/DoD** `pnpm build:web`, `pnpm build:android` once established → builds exit 0. Record manifest and progress, leave runtime verification queued to Q01/Q06. Do not use missing physical devices as a reason to stop development.

### F02 — Versioned API, scoped database transactions and reliable commands

**Goal / requirements** R03, R16. Provide one reusable authorization and write boundary. **Depends** F01. **Scope** Shared protocol, base persistence, health and event primitives. Feature endpoints and real identity verification belong to their own owners.
**Files** Planned packages/contracts/src/http.ts, errors.ts, events.ts and openapi.yaml in packages/contracts; apps/web/src/server/db/scoped.ts, commands.ts and outbox.ts; apps/web/src/app/api/v1/health/route.ts; generated baseline migration in supabase/migrations. Bind migration identifiers in environment.md.
**Interface** `ActorContext(accountId,sessionId,persona,requestId)` furnished only by verified I01; `withActor(ctx, work)`, `commitCommand(ctx, operation, key, requestHash, mutation)`; `appendEvent(tx, event)`; generated stable message keys. GET /api/v1/health → {data:{status:"ok",apiVersion:"v1"}} with no target secrets, person or credential information. Base relations app.command_receipt (unique account/persona/operation/key), app.audit_entry and app.outbox_event. See contracts.md for envelope and constraints.
- [ ] Define runtime-validated DTOs, OpenAPI version policy and both client decoding contracts. Add correlation IDs and localized error keys.
- [ ] Provision version-controlled **local** migrations for app schema, least-privilege connection, transaction-local claims, audit and outbox. Revoke unintended grants; use RLS. Add a scoped transactional read and write service, including no-mutation-on-stale behavior and business-key collision mapping.
- [ ] Check current session, active persona and resource visibility before serving any cached command result; revoke lookup access and do not rerun the write if the actor has lost access. Partition receipts by account and persona. Implement atomic command receipt/result and outbox emission on commit; rollback failures together. Health route reveals readiness level only. Wire actor interface fail-closed until I01 supplies the verified context.
**Acceptance / final cases** Reuse of key+payload returns original scoped result, divergent payload returns conflict, rollbacks leave no event, two roles on reused connection cannot see each other's state. **Checkpoint/DoD** `pnpm check:types` → 0; record migration identifiers, OpenAPI output and final Q01/Q03 cases. No secret/service-role client path.

### F03 — Platform shells, navigation and asynchronous state primitives

**Goal / requirements** R01, R15. Independently build the platform layouts and reusable state controls; domain screens arrive in their slices. **Depends** F01. **Scope** Reusable shells and status components; individual screen data and feature actions belong to their domain modules. **Files** Planned apps/web/src/app/layout.tsx, apps/web/src/ui/{Shell,AsyncSurface,AccountScope}.tsx, apps/web/src/i18n/{ar,de}.json, apps/web/public/manifest.webmanifest; apps/android/app/src/main/java/de/madrasty/app/ui/{SchoolShell,AsyncSurface,SchoolTheme}.kt, res/values and translated resource bundles. See UI reference for details.
**Interfaces** Shell takes actor, active persona, selected permitted child/class, role tabs, and location. AsyncSurface accepts initialLoading, refreshing(with content), ready, empty, error(retry), offlineDraft, conflict and forbidden. Live records are not skeleton content.
- [ ] Bind accessible design tokens, typography, translations, icon meanings and role-specific home/secondary navigation independently on both platforms. Preserve scroll/filter/back focus per tab and clear context between accounts.
- [ ] Implement context-preserving tab routing, sheet dismissal/native back, safe areas/keyboard handling and PWA manifest. Add shimmer/reduced motion policies and separate first load vs background refresh. Use translated announcements for status.
- [ ] Expose the common skeleton, error, retry, copy and date/number-direction primitives to each module; implement desktop navigation preserving mobile task order.
**Acceptance / final cases** Loading never displays a real name or stale previous persona; error never implies empty school; reduced motion remains legible; 320px RTL and long DE labels wrap; TalkBack/VoiceOver focus lands on correct heading. **Checkpoint/DoD** Both builds → exit 0, state names and asset paths documented. Final Q04/Q06 cover the state catalogue on devices.
