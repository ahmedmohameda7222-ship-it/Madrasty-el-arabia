# Communication, notifications and school publishing implementation plan

> For agentic workers: use Superpowers executing-plans and the final-only QA cadence in PLANS.md. Read the [product specification](../specs/product.md), [integration contracts](../specs/contracts.md) and [finance plan](2026-11-19-06-finance.md).

**Goal** Let the right adults contact one another, receive school communications in their chosen correspondence language and find school news and events on iPhone web, desktop web and Android APK. **Stack** Next.js on Vercel, Kotlin/Compose, PostgreSQL RLS, Supabase Auth, private Storage and Cron.

**Planned files and shared constraints** File stems below are checkout-relative. `api/` means `apps/web/src/app/api/v1/`, `server/` means `apps/web/src/server/`, `web/` means `apps/web/src/features/`, `android/` means `apps/android/app/src/main/java/de/madrasty/app/features/` and `dto/` means `packages/contracts/src/`. Each listed API stem ends in `/route.ts`; each HTTP path is relative to `/api/v1`. Add one ordered SQL migration per card under `supabase/migrations/` using the card's named suffix. F01 binds the filename timestamps. Extend the shared OpenAPI and both typed clients with each card. I01 supplies verified account and active persona for every lookup, mutation, media fetch and deep link. Follow F02 actor transactions, field errors, revisions and idempotency. Require Arabic and German, mobile/desktop layouts, accessible focus, loss-of-access and offline states on both clients.

**Verification rule** Every numbered card ends with inspection of the listed paths, migrations/grants, DTOs and its exact acceptance cases, then `pnpm check:types`, `pnpm build:web` and `pnpm build:android` as applicable. Record build outcomes and deferred cases in PROGRESS.md. Only write and run tests beginning at Q01 after the integrated code, isolated Supabase environment, Vercel deployment and signed staging APK exist. Cases below specify expected assertions for Q03/Q05/Q06/Q07; production users, recipients and devices stay outside staging.

**Review focus** A shift change can expose another person's DM. A stale private media link can bypass a removed membership. A second child or device can double a parent's email. Reading a chat on iPhone must cancel its Android reminder. A queued absence correction can overtake the original delivery. Each has an owning card below.

### C01 — Open permitted direct conversations and route official cases

**Requirements / depends** R10. F02, F03, I01, I03, I06, S01, S02, S03, S05. Requires approved guardian links, effective class membership, dated staff roles and office capability grants. **Scope** Consume I06's scoped directory and start/open a pairwise DM or an official case. Message content and attachment capture belong to C02/C03.

**Files** `dto/threads.ts`, `server/comms/threads.ts`, migration `comms_contacts_threads`, `api/threads`, `api/office-cases/[id]`, `web/comms/StartConversation.tsx`, `android/comms/StartConversation.kt`; wire these actions into the existing I06 Directory screens.

**Contract** I06 owns `GET /directory?query=&role=&cursor=` and `GET /directory/{id}`, including individually identifiable professional staff/admin accounts, work fields and permitted actions. Consume I06's target descriptor, rechecking its scoped query at create-or-open and access; S05 owns staff profiles. No additional directory endpoint. `POST /threads {target:{kind:'person'|'office',id},context?:{kind:'homework'|'invoice'|'attendance',id}}` returns `{threadId,kind,canReply,caseId?}`. Resolve canonical person pair in the chosen persona context, or a requester-specific office case; isolate separate guardians' messages. Offices are `student_affairs` and `accounts`. `PATCH /office-cases/{id} {assigneeId?,status?,revision}` returns updated case. Reserve `open|in_progress|closed`; assignment must be to an active office delegate.

- [x] Add private `thread`, `thread_participant`, `office_case` and unique direct-pair/case-origin keys. Resolve professional eligibility on both start and access. Reassignment ends office access for departing delegates and grants successors only the official queue. Check authorization of any referenced record separately.
- [x] Implement create-or-open with business-key protection under duplicate taps. A homework inquiry opens the authorized teacher's conversation with homework reference. An invoice inquiry opens accounts with invoice reference. An absence reply opens its student affairs case. A personal reply stays with that person.
- [x] Bind the I06 search/filter/detail actions to start/open and add inbox choice and staff assignment/status on both clients. Limit previews, counts and search results to the active persona. Display an unavailable contact or record gracefully after a shift, unlink or employment change.

**Acceptance / final cases** Two individually selectable admins can have distinct private conversations with the same parent. A replacement staffer receives open office cases without inheriting private correspondence. Full administration does not confer DM visibility. An unrelated teacher, a second guardian and the wrong office cannot retrieve the original case or attachments by ID. Scope shrink removes stale directory rows. **DoD** Shared checkpoint plus directory/action permission map.

### C02 — Private conversation, replies, reactions, read state and personal archive

**Requirements / depends** R10, R11. C01, F03. **Scope** Message timeline, inbox, search, composer and per-participant activity. C03 supplies validated media IDs; C07 consumes human-message events.

**Files** `dto/messages.ts`, `server/comms/messages.ts`, migration `comms_messages`, `api/threads/[id]/messages`, `api/threads/[id]/state`, `api/threads/[id]/messages/[messageId]/reaction`, `web/comms/Conversation.tsx`, `android/comms/Conversation.kt`; extend `api/threads` with GET.

**Contract** `GET /threads?archived=&q=&cursor=` and `GET /threads/{id}/messages?before=&q=` return scoped cursor pages. `POST /threads/{id}/messages {clientMessageId,body?,attachmentIds?,replyToId?}` returns committed message UUID, ordered thread sequence, author, server time and validated reply/media descriptors. Require content or a ready attachment. Validate all IDs belong to this thread, current user and allowed scope; never accept client author/source. `PATCH /threads/{id}/state {readThroughSeq?,archived?}` changes the caller's state only; max the read sequence across sessions. `PUT /threads/{id}/messages/{messageId}/reaction {emoji|null}` upserts/removes caller's own reaction from the app's supported set. New human messages emit `chat.message_created` with threadId, messageId, sequence and source; receipts, reads, system messages and reactions are distinct.

- [ ] Serialize sequence assignment in the thread and constrain unique sender/clientMessageId. Persist `message`, `message_reaction` and `thread_reader`; record personal read cursors and clear each participant's archive on a new message. Use scoped change refresh with a cursor/poll while active, including reconnect. Limit office read details to authorized participants.
- [ ] Implement in-thread text search, quoted reply navigation, emoji toggle, author and read/sent indicators, archive/restore, latest-message ordering. Both clients retain the typed draft on failure, mark pending/failed messages, retry with the same key and merge the server acknowledgment. System messages are server-authored and replyable where specified.
- [ ] Suppress all user-facing deletion operations for sent messages and conversations, including archive swipe actions. Render only a permitted reference if an associated record becomes inaccessible.

**Acceptance / final cases** Sending while disconnected shows pending/failed and no fabricated receipt. A retry after lost acknowledgment produces one message. A cross-thread quote is rejected, archive is private, a new message restores a thread, and reading on another device clears the user's unread count. Searching for a private phrase as an administrator yields zero unrelated messages. **DoD** Shared checkpoint plus timeline/state/event inventory.

### C03 — Private photos, voice messages and content reporting

**Requirements / depends** R10. C01, C02, F02. Requires a private media bucket and source-controlled type/size/duration limits; real bucket configuration is bound in D02. **Scope** Capture to secure playback, plus scoped handling of a reported message. Production retention follows the school's D-stage decision.

**Files** `dto/chatMedia.ts`, `server/comms/media.ts`, `server/comms/moderation.ts`, migration `comms_private_media`, `api/threads/[id]/uploads`, `api/threads/[id]/uploads/[uploadId]`, `api/threads/[id]/media/[mediaId]`, `api/message-reports`, `api/message-reports/[id]`, `web/comms/MediaComposer.tsx`, `android/comms/MediaComposer.kt`, `web/comms/ReportQueue.tsx`, `android/comms/ReportQueue.kt`.

**Contract** `POST /threads/{id}/uploads {mediaKind:'voice'|'photo',mime,bytes}` returns expiring single-object upload authority and uploadId. `POST /threads/{id}/uploads/{uploadId} {action:'finalize'|'cancel'}` returns `{state,mediaId?}`. Stage privately, verify signature/size/type and decoded image or audio duration, strip location/EXIF and validate sanitized output before ready. Bind owner, purpose, thread, expiry and single message use. Proposed initial caps are 10 MiB per photo and 3 minutes/8 MiB per voice message, checked on server and echoed to clients. Support formats actually offered by the supported iPhone and Android capture/picker flow, converting to a validated interoperable representation before attachment. `GET /threads/{id}/media/{mediaId}` rechecks thread and object scope for every request, including ranges, then streams private content with private/no-store headers. `POST /message-reports {threadId,messageId,reason}`; `GET /message-reports`, `PATCH /message-reports/{id} {state,action?,revision}` limit reviewer to explicitly assigned reports and the flagged item, with audited outcomes. Redaction/retention is a separate privileged operation from ordinary users' archive.

- [ ] Implement private staging → processing → ready/failed/cancelled, enforced byte limits at ingestion, a size-bounded validation worker if necessary, idempotent finalize, expiring orphan cleanup, authorized stream and report queue. Attach only a ready object in C02's send transaction.
- [ ] Support gallery/camera and microphone permission, record start/stop/cancel, photo preview, listen before sending, discard, upload progress, retry and inline viewing/playback on both platforms. Release microphone and revoke temporary local resources on cancel, navigation or logout. Preserve composer/reply context across a failed upload.
- [ ] Distinguish permission denied, unsupported file, failed upload and expired session. Add message report action, reviewer decision and restricted audit with no raw attachment, text or URL.

**Acceptance / final cases** Canceled capture produces zero messages. Lost finalize response and retry bind one attachment. Invalid bytes and oversized files never become playable. Removing a parent link or office assignment denies subsequent reads and range fetches even from an old deep link. A moderator can review a flagged item without searching the whole DM. Validate recording, preview, keyboard overlap, denied permission and playback on actual iPhone PWA and installed APK. **DoD** Shared checkpoint plus bound media limit and privacy inspection.

### C04 — Bilingual broadcast preview and dispatch

**Requirements / depends** R11. F02, F03, I01, S02, S03, S05. Requires active guardian/class and teacher assignments. **Scope** One sender publishes two localized copies to an authorized audience. Transport belongs to C06.

**Files** `dto/broadcasts.ts`, `server/comms/broadcasts.ts`, migration `comms_broadcasts`, `api/broadcasts/preview`, `api/broadcasts`, `web/comms/BroadcastComposer.tsx`, `android/comms/BroadcastComposer.kt`.

**Contract** `POST /broadcasts/preview {audience:{kind:'all_guardians'|'class_guardians'|'all_teachers',classId?},copy:{ar:{title,body},de:{title,body}}}` returns previewId, audience/count by language, copies and expiry; previews contain counts only. `POST /broadcasts {previewId}` returns publication ID and recipient count. Protect both endpoints by grant; a teacher can target guardians of currently assigned classes. Resolve recipients server-side, constrain unique publication/account, preserve intended cohort and final eligibility. Event `broadcast.published` carries broadcastId.

- [ ] Store localized publication, preview fingerprint and private addressed accounts. Recompute authorized audience at publish; if copy, membership or sender eligibility changes, request a new preview or reject access. Persist publication, recipients and outbox atomically.
- [ ] Build compose → counts and both language previews → confirm → history/status on web and APK. Use separate addressed notices/email; deliver once per account even for several children/class roles. Expose aggregate campaign status to authorized senders.

**Acceptance / final cases** A teacher's forged all-school target fails. Two siblings in one class yield one delivery to each linked adult. An inactive account drops before dispatch. No message, preview, email headers or recipient UI leaks the mailing list. German correspondence arrives while the recipient's UI is Arabic. **DoD** Shared checkpoint plus permission and deduplication constraints inspected.

### C05 — Personal notification center, correspondence locale and device subscriptions

**Requirements / depends** R11. F02, F03, I01, I06. **Scope** Durable personal notifications, read state, safe opening and account-bound channel preferences/subscriptions. C07 selects which events create these rows.

**Files** `dto/notifications.ts`, `server/comms/notifications.ts`, migration `comms_notifications`, `api/notifications`, `api/notifications/[id]`, `api/me/push-subscriptions`, `web/comms/NotificationCenter.tsx`, `android/comms/NotificationCenter.kt`.

**Contract** `GET /notifications?unread=&cursor=` lists personal notices and `PATCH /notifications/{id} {read:true}` marks one read. Read I06's `GET|PATCH /account/preferences` and its `correspondenceLocale:'ar'|'de'` field. I06 owns the preferences route and UI. Each notice has owner, event/dedup key, translated template key and protected route context, readAt. `PUT|DELETE /me/push-subscriptions` accepts installation ID and platform-specific W3C subscription or FCM token, binding the verified account/session. Internal `upsertNotice(tx,recipientId,logicalKey,templateKey,target)` returns noticeId. Link resolution requires sign-in, authorized persona and current entity access.

- [ ] Create per-account notice/read rows and session-bound push endpoint records with uniqueness, rotation/revocation on logout, account replacement and inactivity. Keep device tokens private. Integrate session revocation hook with I01; require an authenticated reopen to rotate a subscription after a shared-device sign-in.
- [ ] Implement unread filters, individual read state, badge synchronization and deep links on both clients. Link to the existing I06 preferences and read the account's correspondenceLocale independently of its UI language. Offer push only after a user gesture; on iPhone explain Home Screen installation if necessary. Denied or unavailable push keeps in-app/email available.

**Acceptance / final cases** Reading on one device updates count on the other. A second account never inherits previous notices or tokens. Lost access yields a neutral destination without leaking the former child or content. Web and APK show matching states with RTL and long German strings. **DoD** Shared checkpoint plus device lifecycle and revocation hook inspection.

### C06 — Email and push worker, safe retries and delivery visibility

**Requirements / depends** R11, R16. F02, C05, I04. **Scope** Server transports, durable per-channel attempts and authorized operational history. D03 binds actual identities and environment secrets; staging routes only to the configured sink/allowlist.

**Files** `server/comms/dispatch.ts`, `server/comms/providers/{email,webPush,fcm}.ts`, `server/comms/templates.ts`, migration `comms_delivery`, `api/internal/dispatch`, `api/internal/email-events`, `api/delivery-status`, `api/delivery-status/[id]/redrive`, `web/comms/DeliveryStatus.tsx`, `android/comms/DeliveryStatus.kt`, `apps/web/public/sw.js`, `android/comms/SchoolMessagingService.kt`.

**Contract** Protected Cron `POST /internal/dispatch` claims bounded due jobs by lease, returns counts only. Adapters implement `sendEmail(job)`, `sendWebPush(job,device)`, `sendAndroidPush(job,device)` → accepted(providerId), transient, permanent or uncertain. Use transactional email API with verified school domain (proposed Resend), Web Push VAPID, FCM HTTP v1; configure Auth SMTP separately through D03. Verify signed webhook/replay timestamps for `POST /internal/email-events`, dedupe provider event IDs and reconcile delivered/bounced. `GET /delivery-status?kind=&state=&cursor=` returns restricted institutional status or aggregate failures only. `POST /delivery-status/{id}/redrive {revision}` rechecks operator grant, permitted institutional scope and provider reconciliation state, then queues a safe retry. Store private per-recipient channel rows and per-installation push attempts; unique logical recipient/channel/event and unique installation attempt.

- [ ] Claim jobs using a database-time clock, retry with bounded exponential backoff/jitter and provider idempotency key. On timeout after provider receipt, reconcile with provider ID/idempotency status or flag uncertain for operator review before redrive. Quarantine permanent failures and expire invalid tokens. Recheck current authorization, verified recipient email, language and source revision immediately before ordinary delivery. For I04 invitation.dispatch_requested, the intended pending recipient has no verified account yet: validate current invite generation, expiry, approved family link or staff eligibility, staff-approved destination and locale instead. Send one school invitation containing the provider verification continuation and private claim. Bind webhook/bounce to that generation. Never send academic or financial material to an unverified address.
- [ ] Send one envelope per recipient with translated institutional copy and sign-in-required links. Use generic localized push title/body and an opaque notice ID on both platforms. Keep names, chat text, reasons, grades, balances, IBAN and other identifying content off lock screens and out of logs. Store the institutional delivery status visible to its permitted operator separately from private DM reminders, contents and addresses.
- [ ] Implement sender/provider history, retryable/terminal/uncertain states and scoped redrive through the same deduplication service. Deploy worker schedule and credentials only in D03. Include email bounce and failed-job counts for the authorized staff work queue.

**Acceptance / final cases** Two workers claiming the same notice yield one accepted email. Duplicate or out-of-order webhook cannot regress terminal status. Timeout after acceptance does not trigger blind duplicate send. Expired FCM token disables only that device, and revoked family link or switched session suppresses pending delivery. Institutional mail history never reveals that two people exchanged a private message. **DoD** Shared checkpoint plus provider config names, recipient privacy and delivery-state inspection.

### C07 — Notification rules, timed reminders and replyable absence follow-up

**Requirements / depends** R10, R11, R13, R14. C01, C02, C04, C05, C06, I05, S02, A01, A02, A04, E02, E04, E05, E06, B02, B03, B05. Producers must emit validated committed events with stable UUID and current revision. **Scope** Map events to account-specific notices, email jobs and office chat; C06 performs dispatch.

**Files** `dto/communicationEvents.ts`, `server/comms/{rules,reminders,absenceCases}.ts`, migration `comms_notification_jobs`, extend `server/comms/dispatch.ts`. No public rule-engine endpoint; links and queue status use C01/C05/C06. Both clients show the same localized source and corrections.

| Source | Rule, recipients and recheck |
|---|---|
| I05 `teacher_application.decided` | In-app notice for the verified applicant account; a pending or declined applicant may read their own application status only. Distinguish applicant-visible decision from protected reviewer notes. |
| S02 `family.link_approved`; A02 `attendance.arrival_confirmed` | A newly approved link for an activated adult yields one private in-app notification to that guardian. Actual arrival after an excuse yields one scoped guardian in-app notice, using the committed child/date/revision, with no excuse text. |
| C04 `broadcast.published` | Durable in-app + immediate email to each still-eligible addressed account. Use a fresh correspondence-locale lookup for each recipient. |
| C02 `chat.message_created` | For human chat, notify other eligible participants in-app. For each recipient/thread, persist the instant of the **first** unread human message and schedule one email at exactly +48 elapsed hours (UTC). Later unread messages leave that deadline intact. Under a lock check current readThroughSeq, membership and notification class before claiming. When partially read, recompute the first still-unread human message and its deadline; once the episode's one email has gone out, require a complete read before starting another. Reactions and automated messages never start the timer. |
| A01/A04 `attendance.unexcused_confirmed`, `attendance.corrected` | Confirmed current unexcused record → replyable system message in a separate student affairs case per eligible guardian, plus notice and immediate email in their language. Use record/revision/guardian keys, link the original to correction, cancel undelivered originals, mark sent messages/notifications corrected and deliver a localized correction on each channel that actually received the original. Suppress late or stale sends; reconcile uncertain original delivery before deciding external correction. A correction into unexcused triggers the standard committed absence alert once. Do not expose reason externally. |
| E02/E04 visible mark corrections and E05/E06 `exam.published`, `result.published` | Schedule announcement/change → class guardians. Published periodic assessment or exam result → only linked guardians of affected pupils. Group batch result notice/email by publication batch + account, include authorized individual results inside the account. Corrections to already-visible activity/homework marks and revised periodic/exam results notify the affected recipient once per revision. Never put grades in external copy. Initial activity/homework marks, ordinary lessons and homework stay in their app views. |
| B05 `enrollment.stop_requested`, `enrollment.stop_withdrawn`, `enrollment.stop_approved`, `enrollment.stop_rejected` | Notify the requesting guardian of receipt and each later disposition once in-app, in correspondence language. Recheck current access and revision; staff work queue reads the underlying request. Omit private reasons from external surfaces. |
| B02/B03/B05 invoice, receipt, stop transitions | `invoice.issued` → named payer in-app + email. Schedule default reminders on school-local due date −3 and +3 calendar days (proposed 09:00 local); check positive outstanding balance, reminder period hold, bill revision and authorization at send. Skip expired pre-due milestone on late issue, suppress same-day issue/reminder and obsolete superseded jobs. `payment.recorded` → named payer confirmation/receipt for committed allocations, one per payer/receipt; `payment.reversed` refreshes receipts/balance and historical notice. Never remind an unrelated guardian. Recalculate future eligible jobs on due-date/stop/payment changes, without bursts of missed reminders. |

- [ ] Build idempotent rules, first-unread state, revisioned due jobs and gate checks. For an eligible in-app alert, also enqueue a generic optional push to each registered active device with permission. Keep personal read state authoritative in-app. Differentiate historical invoice read privilege from notice eligibility: a revoked school link cancels pending/future alerts, while its former named payer can open their already issued invoice. Bind exact producer names/payload fields in the shared event registry.
- [ ] Insert projected absence case/message, notice and delivery rows transactionally using source/guardian keys. Let a reply reach assigned student affairs staff; an invoice action goes to accounts. Link corrected sources across devices. Apply school-local date arithmetic only for due-date reminders and UTC elapsed time for chat.
- [ ] Update school dashboards/notification deep links on both platforms. Use authenticated links and safe external copy when source scope changes. Persist event lag and failure counts without exposing payloads.

**Acceptance / final cases** Exercise +47:59:59 vs +48:00:00 across DST, late dispatcher run, second human message, read on another device, reaction-only activity and simultaneous mark-read. A duplicated approval generates one system message/email per guardian; an excused, draft or cancelled day generates none. Exercise correction before delivery, after delivery and between channels. Group class results affecting two siblings, send one alert, conceal each score externally. Paid, disputed unmatched balances without posted allocations, unlinked payer and pending-stop scenarios must each follow their recorded balance/eligibility. **DoD** Shared checkpoint plus reconciled producer/event/channel map with Q05 fake-clock boundaries.

### C08 — School news and monthly events

**Requirements / depends** R12. F02, F03, I01, S01, S02, S03, S05. **Scope** Independently authored school/class posts and dated events, separate from broadcasts and weekly lessons.

**Files** `dto/schoolPublishing.ts`, `server/comms/schoolPublishing.ts`, migration `comms_news_events`, `api/news`, `api/news/[id]`, `api/events`, `api/events/[id]`, `web/comms/{NewsFeed,MonthCalendar}.tsx`, `android/comms/{NewsFeed,MonthCalendar}.kt`.

**Contract** `GET|POST /news`, `GET|PATCH /news/{id}`; `GET /events?month=YYYY-MM&classId=`, `POST /events`, `GET|PATCH /events/{id}`. News has title/body, translatable AR/DE content, audience school/class, draft/published/withdrawn state and UTC publication instant. Event additionally has school-local start, optional exclusive end and all-day flag. Validate date ranges and school timezone. Only authorized publishers edit/publish with revision; scope list/detail separately against current roles, approved child links and class. Reuse S01 school calendar settings and S03 roster lookup.

- [ ] Implement independent scoped news and event stores, lifecycle mutations and indexes. Month queries include events overlapping either boundary. Keep instructional timetable entries in the weekly timetable owned by the school module.
- [ ] Provide compose/preview/publish/withdraw for authorized staff, news list/detail, month navigation, selected day list and class filter on mobile/desktop web and APK. Show accessible list navigation, localized date labels, appropriate empty states and guarded deep links. Publishing ordinary content creates no broadcast mailing.

**Acceptance / final cases** A class-only event is absent from an unrelated family's calendar and direct lookup. A multi-day event remains visible after a month boundary; duplicate submissions do not duplicate the event. Withdrawing a post removes it from readers while retaining the staff record. The weekly lessons view stays independent of school events. **DoD** Shared checkpoint plus publish permission and calendar query inspection.
